glyphplot v0.3.0 checklist

The owner's manual pass (REQ-TEST-030, REQ-TEST-040): run each case in Chrome and Safari, on a desktop and on a phone, mark it, then copy the pass as Markdown into the plan or the pull request. The headless browser tests cover what they can; everything here is what only a real screen, finger, font or screen reader can show.

1. <pre> and canvas

  • The text drawing (a <pre>, one ink) and the canvas drawing show the same cells: same braille line, axes and labels, same row breaks.
  • The canvas is sharp, not blurred, at this screen's pixel ratio; braille dots are square and evenly spaced.
  • The <pre> text can be selected and pasted as the chart.

2. Both renderers

  • The text renderer (fillText per changed cell) and the atlas renderer (glyph masks tinted by compositing) draw the same picture, in the same colours.
  • No glyph is clipped, offset or fringed in either; block and braille glyphs line up across cell edges.
  • Hovering either redraws only the crosshair and readout, with no flicker; the numbers under each chart say how many cells the last frame redrew.
  • The renderer measurement is a separate page: bench/render.html (mise run bench:render).

3. Each mode

  • line: straight segments; step: flat runs with vertical risers; area: filled down to the baseline 0.
  • Two series in each, told apart by colour and named in the legend.

4. Gaps

  • Missing values (null) break the line: two clear holes in the left chart.
  • With spanGaps: true (right) the line runs straight across the same holes.
  • Hovering a hole reads the nearest datum that has a value, never "NaN".

5. A million points

  • The first frame appears within about a second of scrolling here; the time is printed below.
  • Drag, Ctrl/⌘ + wheel or pinch zoom, and hover stay smooth (no visible stutter) at every zoom level down to single points.
  • Zoomed all the way out, the envelope keeps every spike (M4 keeps each column's extremes).
waiting for the chart

6. Mono (one ink)

  • Drawn in a <pre> in one ink: the page's text colour.
  • The three series are told apart by dash pattern (solid, dashed, dotted) with a legend key for each.
  • Dashes stay put when the view pans: they do not crawl.

7. Light and dark

  • theme="light" paints a light ground, theme="dark" a dark one, whatever the page's scheme.
  • Ink, axes and labels are readable on both; the series colours are distinct on both.
  • Focus each (Tab): the outline is in the accent colour and visible on its ground.

8. A theme switch

  • Each button re-colours this chart (and the page buttons every auto chart on the page) at once, with no flash, no reload and no empty frame.
  • "Page dark/light" flips data-theme on <html>; "System" follows the OS setting again: change the OS appearance and the charts follow.
  • "Custom property" sets --glyphplot-series-1 on the element; "Theme object" sets a theme object that wins over it; "Clear" returns to the defaults.
  • The frame count below stays the same through every switch: a theme change repaints, it draws no new frame.

9. Wide labels

  • Large y values (billions) and a title with wide (CJK) glyphs, in German number format (locale="de-DE": 1.234,5).
  • No label overlaps another or the plot; the y gutter widens to fit; wide glyphs take two cells each and nothing after them is shifted.
  • Narrow the window: labels drop rather than collide, and the chart never draws text over text.

10. A resizable container

  • Drag the box's bottom-right corner (desktop) or use the buttons: the chart relays out on every change, without a blank frame.
  • The columns change with the width; the x domain (in data units) stays the same after you zoom in and then resize.
  • Rotating a phone relays out the same way.

11. Data, options and view set from script

  • "New data" replaces the data; "Area" sets options and keeps the view; "Zoom to 20–40" sets the view; "Reset" returns to the fitted view.
  • None of these buttons adds a plot-hover, plot-view or plot-cursor line to the log: events are for the reader's actions only. Dragging the chart does add them.
  • The view printed after each change is in data units and matches what is drawn.

12. Pointer: hover, drag, wheel, brush

  • Hover: a crosshair and a readout of the nearest datum (date and both values) follow the pointer; leaving the chart hides them.
  • Drag pans; Shift + drag brushes a range; Ctrl or ⌘ + wheel zooms about the pointer; a trackpad pinch zooms; the plain wheel scrolls the page; a double-click resets.
  • The control row (− + ↺ ◀ ▶) appears on hover and does the same with single clicks.
  • The log shows one plot-view with final: true at the end of each drag or zoom, and plot-hover only when the datum changes.

13. Keyboard

  • Tab reaches the chart once (one tab stop) with a 2 px outline in the accent colour.
  • ← → step datum by datum and pan past the edge; Home/End; PageUp/PageDown; Shift + ← → pan; + − zoom about the cursor; 0 resets; Enter locks; Shift + Enter twice brushes; Escape hides the readout, a second Escape leaves the chart; 1 and 2 toggle the series.
  • Both charts have the option motion: true: 0 (reset) after a zoom eases back over a moment. With the OS set to reduce motion, the left one jumps instead; the right one, with the motion attribute, still eases.

14. Touch (phone or tablet)

  • One finger moving sideways scrubs the cursor; moving up or down scrolls the page.
  • Two fingers pan; a pinch zooms about its centre; a double tap resets; a long press starts a brush that the finger then extends.
  • Nothing selects text or opens a callout menu; the page does not zoom.

15. Screen reader (VoiceOver, TalkBack, NVDA)

  • The figure is announced by its label; the drawing as an image with a summary (type, series, ranges, count).
  • The cursor is a slider: arrows read the date and each series' value, one datum at a time.
  • The hidden table is reachable (VoiceOver: rotor, Tables): a caption, column headers and a row header a row; 1,000 points read as a 500-row table whose caption gives the count once.

16. The debug build's panic case

  • Served by mise run dev (the debug build) only; the release build says so here instead.
  • The debug-panic chart fires plot-error; the console shows the panic's message and file:line, then "a chart trapped and was stopped" and the error's message.
  • The chart beside it keeps drawing and responding; the shadow stack pointer is the same before and after the trap.
checking the build

17. A lazy element below the fold

  • Reload at the top of the page: the status says "not loaded" and the chart below the spacer draws nothing yet.
  • Scroll down: it loads when it comes within one screen height, and draws by the time it is on screen; the status gives the scroll position at load.
